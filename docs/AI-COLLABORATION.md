# AI 작업 기록 요약

README의 "AI와 작업한 방식" 보충이다. 근거는 비공개 원본 저장소의 커밋, AI가 세션마다 남긴 작업 메모 7건(2026-07-28 ~ 09-17), 이 저장소 코드다. 09-28 건은 공개본을 정리하면서 찾았다.

## 수치

| 항목 | 값 |
|---|---|
| 원본 저장소 커밋 | 10개 (2026-07-27 ~ 08-13), 그중 `Co-Authored-By: Claude` 9개 |
| 원본 저장소가 추적하는 파일 | 28개 (학습 노트북 12개, 학습 문서와 노트, 노트북이 불러오는 코드 2개, `stocks` 어댑터 설정과 가중치) |

```bash
# 원본 저장소에서
git rev-list --count HEAD                                     # 10
git log --format='%b' | grep -c 'Co-Authored-By: Claude'      # 9
git ls-files | wc -l                                          # 28
```

원본 저장소 `.gitignore` 첫 줄이 학습 자료만 버전 관리하도록 돼 있고, 서비스 코드는 `app.py.bak.20260901` 같은 날짜 백업으로만 남아 있다. 그래서 아래 사례는 메모와 현재 코드를 근거로 했다.

## 사례

- LoRA 서빙 오기재 (07-29 메모, 09-02 확인). AI 메모에 "해당 LoRA 얹은 gemma가 브리핑 생성"이라고 돼 있었는데, 같은 메모에 "실제 진행 상태와 다를 수 있음"이라는 단서도 붙어 있었다. 런타임 코드를 grep해 보니 MLX도 어댑터 로딩도 없었다.
- README와 코드 불일치 4건 (09-17). 중복 제거 단계 수, ChromaDB 용도, 라우터 폴백 유무, `.env.example` 변수 목록. 인스턴스화가 0회인 `summarizer.py`, `story_tracker.py`와 렌더 경로 없는 템플릿 3개, 관련 CSS도 이때 지웠다.
- 첫 실행 실패 (09-02). `logs/`가 gitignore 대상이라 clone 직후엔 없는데 `FileHandler`가 디렉터리를 만들지 않는다. 개발 환경엔 `logs/`가 있어서 안 보였다.
- 외장 스토리지 없이 띄우면 벡터 DB가 지워지는 문제 (09-28). 피드백 폴더를 만들면서 로컬 기본 경로가 생기고, 그걸 외장이 붙은 것으로 판정해 사이클 시작 때 폴백 폴더를 통째로 지웠다. 그 안에 ChromaDB가 있었다. 운영은 늘 외장이 붙어 있어서 드러나지 않았고, 공개용 저장소를 새로 받아 한 사이클 돌려 보다 찾았다.
- 로그 해석 오류 두 번 (09-01). 도구의 출구 IP를 외부 스캐너로, 파일 삭제로 난 404를 차단 필터 동작으로 봤다. 이후 메모에 "수치나 응답을 인용할 땐 왜 그 값인지까지 확인한다"는 교정이 남았다.

## 사람이 정한 것과 근거가 없는 것

라우터 마진 0.04에서 0.025로 변경(override 0건), 평가 모델에서 사실 판단 제외, LoRA 미연결 명시, 수동 수집 인증은 메모나 로그에 근거가 있다. Union-Find를 고른 과정, `CATEGORY_WEIGHT` 숫자, Jaccard 0.25와 공유 엔티티 2개는 근거 기록이 없다.

## 한계
