# 개발 노트

운영 중 다룬 주요 문제, 운영 수치, AI 도구 활용 방식, 향후 개선 과제 정리.

## 주요 이슈와 해결

### 룰과 임베딩을 섞은 전문가 라우팅

- 배경: 피드 `category` 라벨 정확도가 매체마다 다름. 룰만 쓰면 라벨 정확도가 낮은 매체에서 오분류, 임베딩만 쓰면 라벨이 확실한 경우까지 흔들림
- 설계: 룰 기본, 임베딩 1위가 룰 후보보다 마진 이상 높을 때만 임베딩 교체(override). `general`·빈 라벨은 임베딩 판정 ([router.py](../analyzers/experts/router.py))
- 마진 조정: 초기값 0.04에서 운영 로그상 임베딩 교체 0건으로 룰 단독과 동일한 결과, 0.025로 하향
- 결과: 2026-06-05 ~ 09-17 판정 5,692건 중 룰 69.2%, 저신뢰 라벨로 임베딩 결정 22.6%, 임베딩 교체 8.2%. 최다 교체 라벨은 `economy`(`stocks`로 77건)
- 후속: 임베딩 교체 판정의 정확도 측정용 층화 표집 200건 골드셋 라벨링 진행 중 ([eval/](../eval/))

### 증분 분석

- 배경: 사이클 소요 시간 9월 기준 중앙값 39분. 사이클 시간 단축을 위해 증분 분석 도입
- 설계: 그날 첫 사이클만 전체 분석. 이후 사이클은 직전 브리핑 테마를 엔티티 역색인에 올리고 신규 기사 매칭. 새 기사가 3건 이상 붙은 테마만 재작성, 미매칭 기사가 3건 이상이면 그 기사끼리 새 테마 최대 5개 생성
- 결과: 로그 기준 매칭률 2.3%. 유지 테마가 15개뿐이라 사이클당 400건대 신규 기사 대부분이 기존 테마에 미매칭
- 부작용: 3건 문턱으로 서술이 그대로인 테마가 연속 브리핑에 반복. 2026-09-16 한 테마는 브리핑 6개에 실렸고 재작성은 3회 ([TRACE_EXAMPLE](TRACE_EXAMPLE.md))

### 자기 평가와 사실 판단 금지

- 배경: 로컬 모델이 가끔 내용 없는 상투적 서술 생성. 같은 모델로 서술 품질을 10점 척도로 채점하고 6점 이하만 재생성
- 현상: 정상 테마 감점
- 원인: 평가 모델이 학습 데이터에 없는 최신 사건을 "사실이 아님"으로 판정
- 조치: 평가 프롬프트에 사실 여부 판단 금지와 기사 내용 신뢰 지시 추가, 원본 기사 제목 함께 입력
- 결과: 평가 244회, 점수 중앙값 7.0, 6점 이하 24.2%

### LLM 출력 후처리

- 현상: 고유명사 한영 혼용(`'베irut'`), 중국어·일본어 혼입, 코드펜스나 설명문이 붙은 JSON 등 반복 패턴
- 조치: 프롬프트로 1차 차단, [ollama_client.py](../analyzers/ollama_client.py)에서 2차 정제. 2자 이상 연속 한자·가나가 섞인 토큰 제거(`美`, `韓` 같은 1자 약칭 유지), think 태그와 코드펜스 제거 후 JSON 블록만 추출
- 결과: 테마 분석, 종합, 재생성, 평가 합계 호출 10,492회 중 JSON 파싱 최종 실패 313회(2.98%)
- 미해결: 주어·목적어 뒤바뀜 오류는 후처리로 검출 불가, 프롬프트로만 대응

### 비용 순 3단계 중복 제거

- 배경: URL 해시만으로는 매체 간 재배포 미검출, 누적 60만 건 전체와 문자열 유사도 비교는 불가
- 조치: URL 해시, 제목 해시, 제목 유사도(0.85) 순서로 필터링. 유사도 비교만 최근 5,000건으로 제한 ([dedup.py](../collectors/dedup.py))
- 결과: 사이클당 원본 중앙값 2,749건 중 406건 잔존. 피드가 최근 기사를 매번 재송출하는 영향이 큼
- 기타: 한 시간 넘는 사이클과 다음 크론의 중첩 방지용 논블로킹 락. 수동 수집 엔드포인트(`/api/collect/now`)는 비밀번호 미설정 시 항상 거부

### 수집 34시간 중단

- 현상: 2026-09-29 수집 34시간 중단
- 원인: requests로 실패한 피드는 feedparser에 URL을 그대로 전달하는데, 내부 urllib에 타임아웃 없음. 연결만 받고 응답하지 않는 피드 하나에 수집 스레드가 묶이고, 해당 스레드가 쥔 수집 락이 해제되지 않아 이후 크론 전부 건너뜀
- 조치: 소켓 기본 타임아웃(20초)과 수집 단계 상한(15분) 추가 ([rss_collector.py](../collectors/rss_collector.py), [scheduler.py](../scheduler.py))
- 재발 방지: 락 점유 3시간 초과 시 에러 로그 기록
- 함께 발견: 역색인이 JSON 파일 하나(259MB)라 기사 1건 삽입마다 파일 전체 재기록. 신규 기사 중앙값 406건 기준 사이클당 100GB 이상 쓰기. 역색인을 SQLite로 이전하고 커밋을 500건 단위로 묶음 ([sqlite_index.py](../storage/sqlite_index.py))

## AI 도구 활용

코드 상당 부분을 Claude Code로 작성. 초기에는 규칙 없이 구현을 AI에 맡기는 방식. 이후 AI가 쓴 코드와 문서를 코드·로그와 대조하는 검증에 중점. 세션 종료 시 맥락이 사라지므로 원본 저장소 `CLAUDE.md`에 세션 시작 시 최근 작업 메모 확인, 종료 시 새 메모 작성 규칙 지정.

대조로 확인한 항목:

- AI 현황 메모의 "LoRA를 얹은 gemma가 브리핑을 생성한다" 기재를 런타임 코드 grep으로 확인, 어댑터 로딩 경로 없음. 현재 구조를 프롬프트 단위 MoE로 정정
- README와 코드 대조로 불일치 4건 확인(중복 제거 단계 수, ChromaDB 용도, 라우터 폴백 유무, `.env.example` 변수 목록). 미사용 모듈 2개와 템플릿 3개 함께 삭제
- 6개월치 로그 집계 결과 군집화와 증분 매칭이 설명과 다르게 동작. 결과 품질은 유지되나 실제 선별은 군집화 대신 점수 컷이 담당. 위 설명과 향후 개선 과제에 반영
- 공개용 저장소를 새로 받아 한 사이클 실행하던 중, 외장 스토리지 없이 기동하면 사이클 시작 시 로컬 ChromaDB를 삭제하는 버그 발견 후 수정. 운영 환경은 항상 외장 연결 상태라 미노출
- 외부 노출 점검 중 인증 없이 열린 수동 수집 엔드포인트 발견 후 차단

이 저장소는 운영 중인 서비스 코드를 공개용으로 정리한 스냅샷. 메모도 AI 작성이며 방향 전환은 대화 중 결정되어 기록 없음. 상세는 [docs/AI-COLLABORATION.md](AI-COLLABORATION.md), 같은 방식을 다른 프로젝트에 적용한 정리는 [MindFlow 케이스 스터디](https://github.com/thefirstplum/mindflow-case-study) 참조.

## 향후 개선 과제

- LoRA 어댑터 런타임 연결: `stocks` 어댑터(rank 8, 13MB) 학습 완료, 런타임 로딩 코드 미구현. 현재는 가중치 고정 상태에서 프롬프트만 교체하는 구조
- 군집화 개선: 548건이 493개 군집으로 나뉜 날이 있을 만큼 묶음 효과가 낮음. 실제 선별은 기사 수, 카테고리 가중치, 매체 수로 매긴 점수 컷이 담당. 기사 쌍 전수 비교(O(n²))라 수집량 증가 시 병목
- 라우팅 정확도 측정, 전문가 대표벡터를 손으로 쓴 문구의 평균에서 실제 기사 centroid로 교체
- 자동화 테스트 도입. 현재는 수정 후 한 사이클 실행과 로그로 확인
- 경험값으로 정한 카테고리 가중치, Jaccard 0.25 등 파라미터의 근거 검증
